# Архитектура web-приложения

Документ фиксирует границы слоёв `apps/web` и правила, по которым раскладывается
код. Он описывает текущее состояние после разбиения крупных досок панели, а не
идеальную схему «как надо будет когда-нибудь».

## Слои

Сверху вниз — направление зависимостей. Нижний слой не знает о верхнем.

| Слой | Где | Ответственность |
| --- | --- | --- |
| `app` | `src/app` | Маршруты Next.js: загрузка данных на сервере, проверка сессии и прав, композиция. Доменной логики и больших кусков разметки здесь нет. |
| `widgets` | `src/widgets` | Самодостаточные блоки страниц: лендинг, оболочка панели (сайдбар, командное меню, шапка). |
| `features` | `src/features` | Одна продуктовая область: экраны, расписание, кампании, публикации, команда, медиатека, структура, мониторинг, тариф, журнал, плеер, привязка. |
| `shared` | `src/shared` | То, что нужно двум и более фичам: клиент панели, запросы публикаций, форматирование, CSRF, плюрализация. |
| `components` | `src/components` | Визуальная система (Atomic Design): `ui/*` — примитивы и паттерны без знания о домене, `visual/*` — эффекты и айдентика. |
| `domain` | `src/domain` | Чистые правила продукта, общие для web и API: права, здоровье экранов, правила плейлистов, расписания, релизов. |
| `player` | `src/player` | Клиентское окружение телевизора: хранилище учётных данных, протокол, предзагрузка. |
| `server` | `src/server` | Доступ к API из серверных компонентов и проверка сессии. |

`pages`-слой FSD не создаётся: его роль выполняют `app/**/page.tsx`.

## Как устроена фича

```
features/<domain>/
  model.ts    типы фичи, если они нужны нескольким её файлам
  api.ts      запросы к API, разбор ошибок, фоновая загрузка
  format.ts   подписи, цвета, форматирование дат и чисел
  config.ts   константы и справочники
  ui/         компоненты; один файл — одна зона ответственности
  useX.ts     хук, если у экрана сложная механика (таймеры, сокет, опрос)
```

Крупная доска (`CampaignsBoard`, `ScheduleBoard`, `TeamBoard`, …) остаётся
тонким оркестратором: состояние, обработчики и компоновка. Таблица, форма,
диалог и карточка деталей живут в отдельных файлах `ui/*`.

Локальные типы, константы и справочники остаются рядом с владельцем. В `shared`
уезжает только то, что реально используется несколькими фичами.

## Правила

- **Страница только собирает.** `app/**/page.tsx` проверяет сессию, получает
  данные, маппит их в тип фичи и рендерит компонент. Если разметки больше
  экрана — она уезжает в `features/*/ui` (например, `ScreenDetail`).
- **Запросы — через общий клиент.** В панели это `dashboardRequest`: он ставит
  `x-company-id`, CSRF для изменяющих методов и превращает сетевой сбой в
  сообщение «Сервер недоступен». Прямой `fetch` остаётся только там, где нужен
  `multipart/form-data` (загрузка файлов) или другой контракт (привязка плеера).
- **Тела запросов не дублируются.** Формы запросов к `/api/dashboard/releases`
  собраны в `shared/api/releases.ts`.
- **Одинаковые подписи не расходятся.** Версия плейлиста описывается один раз
  в `shared/lib/playlist-version.ts`; области действия — в
  `shared/lib/scope-label.ts`.
- **Фичи не импортируют друг друга.** Общее поднимается в `shared`; типы можно
  реэкспортировать из `model.ts` фичи, чтобы не плодить одинаковые объявления.
- **Ошибки не глотаются.** Фоновый опрос может молчать осознанно (следующий тик
  повторит), действие оператора — нет: отказ показывается сообщением, кнопка
  выходит из занятого состояния.
- **Поведение важнее формы.** При разбиении сохраняются интервалы опроса,
  кадры WebSocket, оптимистичные обновления и тексты ошибок.

## Где что искать

- Оболочка панели — `widgets/dashboard-shell/ui`.
- Лендинг — `widgets/landing/ui`, страница `app/page.tsx` только рендерит его.
- Плеер показа — `features/player-display` (`config.ts`, `api.ts`, `clock-sync.ts`,
  `telemetry.ts`, `PlayerStateScreen`, хуки).
- Привязка телевизора — `features/pairing` (`api.ts`, `usePairing.ts`, `ui/`).
- Общие помощники — `shared/lib` (`plural`, `format`, `relative-time`, `csrf`,
  `scope-label`, `playlist-version`), общий клиент — `shared/api`.

## Проверки

Из корня: `pnpm check` (typecheck + сборка web), `pnpm test` (API, vitest).
Отдельно: `pnpm --filter @shawty/web typecheck`, `pnpm --filter @shawty/web build`,
`pnpm --filter @shawty/api test`.

## Известные ограничения

- Сервисы API (500–700 строк) не переписывались: риск выше выгоды, у них есть
  тесты и стабильные контракты.
- `versionOptions` в `DeliveryBoard` намеренно оставлен как было (берёт
  `versions[0].id` для каждой версии плейлиста). Это отдельное продуктовое
  решение, а не следствие реорганизации.
- Обзор сети (`app/dashboard/page.tsx`) остаётся одной страницей из четырёх
  блоков: каждый блок используется только здесь.
- `currentItemIdRef` в плеере не заполнялся и до разбиения — поведение
  сохранено намеренно.
