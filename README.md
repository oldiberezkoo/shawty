# SHAWTY

`DIGITAL SIGNAGE` · `CONTROL PLANE` · `UZ`

Платформа управления цифровыми экранами: кампании с расписанием, публикация
контента на телевизоры с подтверждением фактической доставки.

Полный план работ и архитектурные решения — в [`PLAN.md`](./PLAN.md).

---

## `[01]` Что работает

`ПРОДУКТ` · `ПАНЕЛЬ · ПЛЕЕР · ЛЕНДИНГ` · `ФАКТ`

| `МОДУЛЬ` | `ФАКТ` |
|---|---|
| **Дашборд** | Вход, роли и область доступа, список экранов с состоянием сети. |
| **Привязка по QR** | Короткоживущий код, одноразовое подтверждение, ограничение частоты, проверка лимита тарифа, отдельные учётные данные устройства. |
| **Канал устройства** | WebSocket с авторизацией по короткоживущему токену, heartbeat, подтверждение применения публикации. |
| **Управление экранами** | Отключение, отвязка, ротация секрета без визита к ТВ. |
| **Кампании и расписание** | Даты, приоритет, области показа, окна по дням недели и часам, часовой пояс филиала, согласование перед запуском. |
| **Автосмена программы** | Фоновая публикация в момент, когда окно кампании начинается или заканчивается. Телевизор узнаёт момент смены заранее и готовит следующую программу до переключения. |
| **Календарь показа** | Что и когда идёт на каждом экране, и кто мог бы пойти вместо этого. |
| **Мониторинг** | Интервалы простоя, лента событий, доступность за период по трём уровням — «на связи», «на связи со старым контентом», «недоступен» — и CSV. |
| **Журнал действий** | Кто и когда отвязывал экраны, удалял файлы, согласовывал кампании и публиковал контент. |
| **Отчёт по кампаниям** | Охват, применение, подтверждённые старты и время показа — с точной привязкой к кампании, а не по датам. |
| **Команда** | Приглашение по одноразовой ссылке, регистрация прямо по ней, смена роли и приостановка сотрудников, матрица прав в интерфейсе. |
| **Тариф и потребление** | Сколько экранов, сотрудников и места осталось, предупреждение об истечении подписки поверх всех экранов. |
| **Интерфейс** | Боковая навигация с иконками, таблицы сворачиваются в карточки по ширине контейнера, на узком экране меню выезжает поверх страницы, поля не разъезжаются при вводе с телефона. |

## `[03]` Дизайн

`WEB` · `ОДИН АКЦЕНТ` · `HAIRLINE` · `PIXEL`

Дизайн-система — часть веба: токены и темы живут в
`apps/web/src/app/globals.css`, справочник — в `apps/web/design.md`, примитивы
и фирменная графика — в `apps/web/src/components/{ui,visual}`. API и infra о
внешнем виде не решают: API отдаёт данные, веб их рисует.

| `ПРИНЦИП` | `ПРАВИЛО` |
|---|---|
| **Квадратные углы** | Радиусы запрещены глобально (`border-radius: 0 !important`), включая порталы Base UI. Форму задают линия и заливка. |
| **Один акцент** | `#ff4f7b` в тёмной теме и `#c2143f` в светлой. Он отмечает интерактив, живое состояние и `<em>` в заголовке. Статусы и ошибки остаются монохромными, иначе акцент перестаёт что-либо значить. |
| **Hairline вместо тени** | Глубина — разницей поверхностей (`#0a0a0a` → `#111111` → `#161616`) и линией 1px. `box-shadow` выключен. |
| **Mono-капс для служебного** | Номера разделов `[01]`, метки, таблицы, кнопки, навигация — Geist Mono 10–11px с трекингом `0.08em`. Текст и заголовки — Geist Sans. |
| **Пиксель-арт вместо фото** | Знак — кристалл 7×10, иконки — битмапы 9×9, фоны — дизеринг-сцены на canvas. Фотографий и декоративных градиентов нет. |
| **Тема по системе** | Светлая базовая, тёмная — класс `.dark`. Ручной выбор хранится в `localStorage` и применяется до первой отрисовки, поэтому страница не мигает. |
| **Короткое движение** | Переходы 90–220 мс, появление — на 2px вверх. При `prefers-reduced-motion` анимации выключаются, сцена остаётся статичным кадром. |

### `ТИПОГРАФИКА`

| `РОЛЬ` | `ШРИФТ` | `РАЗМЕР` |
|---|---|---|
| Заголовок страницы | Geist 500 | `clamp(1.5rem, 1.15rem + 1.2vw, 1.875rem)`, `-0.035em` |
| Заголовок лендинга | Geist 500 | `clamp(2.5rem, 1.35rem + 3.2vw, 3.5rem)`, `-0.045em` |
| Текст | Geist | `14px` / `1.5`, трекинг `-0.006em` |

| Числа | Geist | `tabular-nums` |

### `ГРАФИКА`

- **Знак** — «ступенчатый кристалл» 7×10, один SVG-path, `crispEdges`,
  `currentColor`.
- **Иконки** — битмапы 9×9 для бренда и состояний; функциональные действия
  остаются линейными (`lucide-react`).
- **Дизеринг** — canvas с одним пикселем на ячейку, три тона, Bayer 4×4,
  12 fps. Сцены `crystals` и `flow`; палитра читается из `--bg` и
  `--accent-rgb`, поэтому смена темы перекрашивает канвас без перезагрузки.
- **Тема** — светлая и тёмная, переключатель в шапке; `theme-color` меняется
  вместе с классом `.dark`.

Практические правила: цвет — токеном (`bg-surface`, `text-muted`), таблицы —
`.stack-table` (сворачиваются в карточки по ширине контейнера), поля —
`.field`, заголовок страницы — `.page-title`, метка — `.label`. Полный набор
токенов и классов — в
[`apps/web/README.md`](./apps/web/README.md#04-дизайн-система).

## `[04]` Запуск

`NODE ≥ 20.9` · `PNPM 11` · `FFMPEG`

| `ТРЕБОВАНИЕ` | `ЗАЧЕМ` |
|---|---|
| Node.js ≥ 20.9 (проверено на 26.5) | Runtime обоих приложений |
| pnpm 11 | Workspace и единая блокировка зависимостей |
| ffmpeg и ffprobe в `PATH` | Проверка и транскодирование медиа, с этапа P2 |

```bash
pnpm install
pnpm db:migrate          # применить миграции
pnpm db:seed             # демо-данные
pnpm dev                 # API :4000 + веб :3000
```

Веб: http://localhost:3000, API: http://localhost:4000.
Браузер ходит в `/api/*` на веб-оригине, Next проксирует запросы в API,
поэтому cookie сессии и CSRF остаются same-origin. WebSocket плеера
подключается к API напрямую (в dev — `ws://localhost:4000/ws/device`).

Демо-вход: `owner@shawty.uz` / `demo1234`

## `[06]` Структура

`MONOREPO` · `4 ПАКЕТА`

```
apps/web/              Next.js: страницы, компоненты, дизайн-система
apps/api/              Hono + ws + Drizzle + SQLite, HTTP и WebSocket
packages/contracts/    общие схемы, DTO и кадры WebSocket
infra/                 reverse-proxy и упаковка (Фаза 5)
data/                  SQLite, медиа и секреты (gitignored)
```

Правило: `apps/web` не импортирует код API — только `@shawty/contracts`.
Веб получает данные через HTTP API; серверные страницы передают cookie сессии
в API и не читают базу. Чистые функции (`domain/playlist`, `domain/release`,
`domain/monitoring`) остаются в вебе, потому что исполняются в браузере плеера.

## `[07]` Настройки окружения

`ENV` · `API` · `ПЛЕЕР`

| `ПЕРЕМЕННАЯ` | `ПО УМОЛЧАНИЮ` | `НАЗНАЧЕНИЕ` |
|---|---|---|
| `PORT` | `4000` | Порт API |
| `API_INTERNAL_URL` | `http://localhost:4000` | Куда Next проксирует `/api/*` |
| `NEXT_PUBLIC_WS_URL` | `ws://<host>:4000/ws/device` | Адрес WebSocket для плеера |
| `NEXT_PUBLIC_APP_URL` | `http://localhost:3000` | Публичный адрес веба для ссылок плеера |
| `PUBLIC_URL` | `http://localhost:3000` | Адрес, попадающий в QR. **На телевизоре должен быть доступен из сети.** |
| `SERVER_SECRET` | создаётся в `data/.secret` | Ключ HMAC для кодов привязки и секретов устройств. В продакшене задать явно |
| `PAIRING_QR_CARRIES_CODE` | `false` | `true` — код попадёт прямо в QR (быстрее, слабее) |
| `PAIRING_CODE_TTL_MS` | `300000` | Срок кода подтверждения, 5 минут |
| `PAIRING_MAX_ATTEMPTS` | `8` | Попыток ввода кода до блокировки сессии |
| `PLAYER_OFFLINE_AFTER_SEC` | `90` | Порог «нет связи» |
| `PLAYER_SCHEDULE_HORIZON_DAYS` | `7` | Горизонт расписания, закладываемый в манифест |
| `PLAYER_PREFETCH_BEFORE_MS` | `600000` | За сколько до смены программы экран готовит публикацию |
| `DEVICE_ACCESS_TOKEN_TTL_MS` | `900000` | Срок токена устройства |

Полный список — в `apps/api/src/config/server.ts`.

Важно: это зона **филиала**. Компания одна, а филиалы в разных зонах — окно
«с 09:00» в них наступает в разное время.

## `[08]` Важные решения

`ПОЧЕМУ ТАК` · `НЕ СЛУЧАЙНО`

| `РЕШЕНИЕ` | `ПОЧЕМУ` |
|---|---|
| **Никаких постоянных токенов в URL** | Адрес попадает в историю браузера, логи и стороннюю аналитику. Устройство обменивает секрет на короткоживущий токен, а WebSocket принимает токен первым кадром, не в адресе. |
| **Код подтверждения не в QR по умолчанию** | QR несёт только идентификатор сессии, а восьмизначный код человек вводит руками. Тот, кто просто сфотографировал экран, не сможет ни подтвердить привязку, ни перехватить устройство: для обмена требуется локальный nonce, который телевизор никогда не показывает. |
| **Данные одной компании недоступны другой** | Проверка идёт на уровне запроса, а не фильтрацией результата. |
| **Что показывается, решает сервер** | Плеер не знает про кампании, приоритеты и пересечения окон: два телевизора с чуть разными версиями плеера показывали бы разное в один и тот же момент. Сервер отдаёт готовую программу и момент следующей смены, а экран готовит следующую публикацию заранее. |
| **Окна считаются в часовом поясе филиала** | «С 09:00» в Самарканде и в Ташкенте — это разное время, хотя цифры выглядят одинаково. Перевод стрелки проверяется тестами на реальных зонах. |
| **Простой считается от последнего heartbeat** | Насос замечает обрыв с задержкой до интервала проверки; если считать от момента обнаружения, отчёт сдвинет время недоступности и он перестанет сходиться с журналом устройства. |
| **Три уровня достоверности, и третий не утверждается** | Доступен экран — показывает ли он нужную публикацию — видел ли это человек. Камер и датчиков внимания нет, поэтому счётчика показов в продукте нет и не будет. В выгрузках колонка названа `started_plays`, а не `views`. |
| **Журнал действий пишется в сервисе, а не в маршруте** | Иначе отвязка экрана из скрипта прошла бы без следа, а журнал выглядел бы полным. Фоновая публикация по расписанию в журнал не пишется: её никто не инициировал. |
